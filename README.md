# data-quality-dashboard

Dashboards for data quality control in the NCATS Biomedical Data Translator project.

Each dashboard lives in its own top-level folder and is a standalone Python project with its own dependencies, tests, and CI workflow.

## Dashboards

| Dashboard | Description |
|---|---|
| [graph-metadata-dashboard](graph-metadata-dashboard/) | Dashboard for exploring and comparing knowledge graph metadata generated by [ORION](https://github.com/RobokopU24/ORION) |

## Repository layout

```
data-quality-dashboard/
├── .github/workflows/        # CI workflows, one per dashboard
├── graph-metadata-dashboard/ # standalone dashboard project
└── README.md
```

## Getting started

Each dashboard is managed with [uv](https://docs.astral.sh/uv/). From a dashboard folder:

```bash
cd graph-metadata-dashboard
uv sync --extra dev
uv run pytest
```

See each dashboard's own README for run and deployment instructions.

## Adding a new dashboard

1. Create a top-level folder named `<name>-dashboard/` with its own `pyproject.toml` and `uv.lock`.
2. Add a workflow at `.github/workflows/<name>-dashboard-tests.yml`, scoped with `paths:` filters to the dashboard folder and its own workflow file, and with `defaults.run.working-directory` set to the dashboard folder.
3. Add the dashboard to the table above.

To import an existing repo with its history, rewrite it into a subfolder with `git filter-repo --to-subdirectory-filter <name>-dashboard` in a fresh clone, then merge it in with `git merge --allow-unrelated-histories`.

## Shared code

Dashboards are currently independent. When utilities need to be shared across dashboards, factor them into a top-level `common/` package and add it as a dependency of each dashboard that uses it.
